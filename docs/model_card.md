# Model Card

## Model Name

RNA Thermoswitch ML Screening model bundle

## Model Type

The current workflow fits an in-memory scikit-learn model bundle:

- calibrated GradientBoostingClassifier for simulation-derived pass probability;
- GradientBoostingRegressor for T50 prediction;
- RandomForestRegressor for slope70 prediction.

## Intended Use

The model bundle is intended for simulation-guided candidate prioritisation. It ranks RNA thermoswitch candidates under thermodynamic simulation assumptions and supports generation of a Top-K shortlist for future experimental follow-up.

Appropriate uses:

- portfolio demonstration of scientific ML workflow design;
- candidate ranking from thermodynamic simulation-derived features;
- evaluation of imbalanced classification, calibration, regression, and Top-K ranking;
- generating a reproducible shortlist and order-sheet artefact from the canonical processed dataset.

## Non-Intended Use

The model must not be used to claim:

- wet-lab validation;
- experimentally proven RNA thermoswitch behaviour;
- biological confirmation in cells or in vitro;
- clinical, industrial, or production readiness;
- guaranteed genetic control performance.

The model should not be deployed as a design authority without additional experimental validation, robustness testing, and domain-specific review.

## Training Data

Canonical dataset:

```text
data/processed/library_combined.csv
```

The dataset contains 700 processed RNA candidate rows. Labels and regression targets are derived from thermodynamic simulation outputs, not wet-lab assays.

Large raw simulation sweeps are excluded from the lightweight public repository workflow.

## Inputs

The model feature extractor uses inference-available sequence and design fields:

- RNA sequence;
- RBS start/end coordinates;
- design metadata such as `extra_pairs`, `pGC`, and `loop_len`;
- engineered sequence length and GC fraction;
- dinucleotide and trinucleotide frequency features;
- fixed-length RBS-window one-hot features.

Observed target columns are excluded from inference features.

## Outputs

The model bundle produces:

- `p_pass`: predicted probability of meeting the thermodynamic simulation-derived pass specification;
- `t50_pred`: predicted T50;
- `slope70_pred`: predicted slope at 70 C.

Downstream scripts use these outputs to generate:

- ranked Top-K predictions;
- diversity-filtered shortlist;
- QC-filtered clean shortlist;
- practical order sheet.

## Evaluation Protocol

Canonical evaluation is generated by:

```text
scripts/evaluate_model.py
```

Evaluation uses:

- deterministic stratified train/test split;
- 5-fold stratified cross-validation when class counts allow it;
- threshold selection from training predictions using the configured F-beta mode;
- ranking metrics for K = 10, 20, and 50;
- expected random-ranking baseline values for Top-K context.

The generated report is:

```text
reports/model_evaluation.md
```

## Metrics

The canonical report includes:

- Average Precision / PR-AUC as the lead classification metric;
- ROC-AUC as a secondary classification metric;
- Brier score for calibration context;
- confusion matrix at the selected threshold;
- Precision@K and Recall@K for K = 10, 20, and 50;
- T50 MAE and R2;
- slope70 MAE and R2;
- cross-validation mean and standard deviation summaries;
- expected random-ranking baseline for Top-K metrics.

Metrics should be interpreted as performance against thermodynamic simulation-derived labels, not experimental outcomes.

## Limitations

Key limitations:

- labels and targets are simulation-derived;
- no wet-lab validation has been performed;
- canonical processed dataset is small for biological sequence modelling;
- sequence-similarity-aware validation is not yet implemented;
- generated full-library predictions are in-sample scoring artefacts;
- only an expected random-ranking baseline is currently included;
- production-style saved model artefacts are not yet published;
- F1 openness plotting uses stored simulation curve values in the lightweight workflow rather than fresh NUPACK recomputation.

See:

```text
docs/limitations.md
```

## Ethical and Scientific Caveats

This project should be presented as an honest scientific ML workflow, not a validated biotechnology product. Any real-world biological use would require experimental validation, biosafety review, domain expert assessment, and context-specific testing.

The safest language is:

> The model is trained on thermodynamic simulation-derived targets, so results should be interpreted as candidate prioritisation under simulation assumptions rather than experimental validation.
